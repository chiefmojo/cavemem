# src/

## Responsibility

Implementation of the compression engine: turn arbitrary session prose into deterministic caveman-grammar output without ever mutating technical tokens, and reverse enough of it (`expand`) for human-facing reads. Also owns the privacy scrubbers that must run before anything reaches storage or logs, and the token estimator used to prove compression is working.

## Design

- **`tokenize.ts` — single authority for technical-token preservation.** Declares `SegmentKind` (`'fence' | 'inline-code' | 'url' | 'path' | 'command' | 'version' | 'date' | 'number' | 'identifier' | 'heading' | 'prose' | 'newline'` — `command`/`newline` are declared but no rule currently emits them) and `Segment { kind, text, preserved }`. The `RULES` table is a priority ladder — fence(100) ` ````…```` `/`~~~…~~~`, inline-code(90) `` `…` ``, url(80) `https?://…`, heading(70) line-scoped `/^#{1,6}\s[^\n]*$/gm`, path(60) POSIX/`~/`/Windows-drive forms, date(50) ISO-8601 with optional time, version(40) `v1.2.3[-+prerelease]`, number(30), identifier(20) snake/kebab/camelCase. `tokenize()` is a single pass: run every rule's global regex (zero-width-match guard bumps `lastIndex`), collect `Span`s, then resolve overlaps greedily — sort by start ASC / priority DESC / wider span first, sweep with a cursor and drop any span starting before it. Unclaimed gaps become `preserved: false` prose segments. `detokenize()` is the trivial inverse (join texts). Both `compress` and `expand` mutate only non-preserved segments, which is what makes byte-for-byte preservation a structural guarantee rather than a per-rule promise.
- **`lexicon.ts` + `lexicon.json` — rules as data.** The JSON holds per-intensity arrays (`fillers`, `articles`, `hedges`, `pleasantries`), per-intensity abbreviation maps, and one flat `expansions` reverse map. Imported via `import lex from './lexicon.json' with { type: 'json' }`; `lexicon.ts` exposes typed accessors only: `fillersFor`, `articlesFor`, `hedgesFor`, `pleasantriesFor`, `abbreviationsFor` (keyed by `Intensity`), and `expansions()`. Intensities are cumulative — `lite` = fillers + pleasantries, `full` adds hedges + articles + the standard abbreviation set (`configuration→config`, `function→fn`, …), `ultra` adds more hedges and aggressive forms (`configuration→cfg`, `and→&`, `with→w/`, `before→b4`).
- **`compress.ts` — the deterministic compressor.** `compress(input, { intensity = 'full' })` tokenizes, passes preserved segments through verbatim, and runs `compressProse` on prose: `removePhrases` (longest-first sorted alternation, `\b…\b` case-insensitive, deleted outright) in fixed order pleasantries → hedges → fillers → articles, then `abbreviate` (per-entry `\b…\b` regex with `matchCase` preserving ALL-CAPS and Capitalized shapes via `escapeRe`), then `collapseWhitespace` (space/tab runs → single space, pad around `\n`, drop space before `.,;:!?`, 3+ newlines → 2). `compressProse` slices off leading/trailing whitespace before mutating and re-attaches exactly one boundary space or newline afterwards — the seam guard so `at /tmp/x` never fuses into `at/tmp/x` when joined with preserved tokens (regression-pinned in `test/compress.test.ts`). Final pass strips ` + punctuation` across the joined output. Pure functions throughout; same input always yields same output.
- **`expand.ts` — lossy inverse.** `expand()` tokenizes, builds one alternation regex from `expansions()` keys sorted longest-first (`w/o` must beat `w`), and replaces only in non-preserved segments, lowercasing the match to look up the map and re-applying case via `matchCase`. Dropped fillers/articles/hedges are gone by design; abbreviations come back.
- **`privacy.ts` — redaction at the boundary.** `redactPrivate()` strips `<private>…</private>` (non-greedy dotall, case-insensitive `PRIVATE_RE`) and, defensively, truncates from any unclosed `<private>` to end-of-input. `redactSecrets()` masks secret-shaped substrings with `[REDACTED]`: `PEM_RE` private-key blocks, `BEARER_RE` (keeps the `Bearer ` prefix), `OPENAI_KEY_RE` (`sk-…`), `AWS_KEY_RE` (`AKIA…`), `GITHUB_TOKEN_RE` (`gh[pousr]_…`), `GITHUB_FINE_PAT_RE`, `SLACK_TOKEN_RE` (`xox…`), and `ASSIGNMENT_RE` — generic `key = value` / `key: value` where the key ends in `api[_-]?key|secret|token|password|passwd|authorization|[_-]key`; the `[\w-]*` prefix catches env-var-style names (`STRIPE_SECRET_KEY`, `aws_secret_access_key`) that a bare `\b` would miss, while requiring `_`/`-` before a bare `key` keeps camelCase identifiers like `cacheKey` safe. Values match quoted (`"`/`'`) or bare ≥8 chars so closing quotes survive. `looksSecretish()` gates assignment redaction: rejects <8 chars, function-call shapes (`deriveCacheKey()`), and plain dictionary words — keeps false positives off ordinary code and prose.
- **`count.ts` — cheap stable metric.** `countTokens(text)` = `Math.max(wordCount, Math.round(chars / 4))`, `0` for empty. Not a real tokenizer; consistent enough for before/after comparisons in `evals/`, the CLI, and the ≥30% compression benchmark.
- **`types.ts` — shared vocabulary.** `Intensity = 'lite' | 'full' | 'ultra'`. (`Segment`/`SegmentKind` live in `tokenize.ts` and are re-exported through `index.ts`.)
- **`index.ts` — public export root.** Re-exports `compress`, `expand`, `tokenize` (+ `Segment`, `SegmentKind`), `redactPrivate`, `redactSecrets`, `countTokens`, and the `Intensity` type. This module is what `package.json`'s `.` export points at; `./lexicon` is the second (and only other) public root, for consumers that want raw lexicon access.

## Flow

Compression: `compress()` → `tokenize()` splits input into preserved/prose segments → per prose segment `compressProse()` runs removePhrases(pleasantries) → removePhrases(hedges) → removePhrases(fillers) → removePhrases(articles) → `abbreviate()` → `collapseWhitespace()`, with boundary whitespace sliced off and restored → segments joined → trailing-space-before-punctuation cleanup. Expansion: `expand()` → `tokenize()` → single longest-first alternation replace over prose segments only. Privacy runs before compression at the call site: `MemoryStore` (packages/core) applies `redactPrivate` → optional `redactSecrets` (per `settings.privacy.redactSecrets`) → `compress`, so redacted text is what gets compressed and stored.

## Integration

- `index.ts` is the only import surface for downstream packages: `packages/core/src/memory-store.ts` (write boundary — imports `compress`, `expand`, `redactPrivate`, `redactSecrets`), `apps/worker` (`server.ts` and `embed-loop.ts` use `expand` for the viewer API and before embedding), `apps/mcp-server` (`server.ts` uses `redactPrivate`/`redactSecrets` on tool inputs), `apps/cli` (`commands/compress.ts`, `opencode-bridge.ts`), and `evals/src/bench.ts` (`compress`, `countTokens`). Cross-package imports of internal files (`compress.ts`, `tokenize.ts`, …) are a defect — go through `.` or `./lexicon`.
- `tokenize.ts`'s rule table is the contract the rest of the repo relies on: CLAUDE.md rule 2 names it the single authority, so any new technical-token kind is added there and pinned by `test/compress.test.ts` before anything else changes.
- Behavior is locked by `test/compress.test.ts` (preservation, determinism, intensity ordering, seam-spacing regression, redaction cases) and `test/fixtures.test.ts` (benchmark corpus ≥30% compression); lexicon edits require a round-trip fixture and green `pnpm --filter @cavemem/compress test`.
