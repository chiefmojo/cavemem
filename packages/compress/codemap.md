# packages/compress/

## Responsibility

The compression engine — the package that makes "memory is stored compressed" true. It owns the deterministic caveman-grammar compressor (`compress`), its inverse for human-facing reads (`expand`), the technical-token tokenizer that guards code/paths/URLs/numbers from mangling, the privacy scrubbers (`redactPrivate`, `redactSecrets`), and a cheap token estimator (`countTokens`). Every write path in cavemem funnels prose through this package before it hits SQLite; every human-facing read path runs stored content back through `expand`.

## Design

- **Tokenizer is the single authority** (`src/tokenize.ts`): one pass collects regex spans for technical tokens (fenced code, inline code, URLs, headings, paths, dates, versions, numbers, identifiers) and resolves overlaps by a priority ladder — fence(100) > inline-code(90) > url(80) > heading(70) > path(60) > date(50) > version(40) > number(30) > identifier(20). Overlap resolution is greedy: sort by start ASC / priority DESC / wider-span first, drop anything starting before the cursor. Everything not claimed becomes a `prose` segment (`preserved: false`). This is why code, URLs, file paths, shell commands, version numbers, dates, numeric literals, and quoted identifiers survive compression byte-for-byte — both `compress` and `expand` only mutate non-preserved segments.
- **Lexicon is data, not code** (`src/lexicon.json` + thin typed accessors in `src/lexicon.ts`): per-intensity word lists (`fillers`, `articles`, `hedges`, `pleasantries`), per-intensity abbreviation maps, and one reverse `expansions` map. Intensities are cumulative: `lite` drops fillers/pleasantries; `full` adds hedges, articles, and the standard abbreviation set; `ultra` adds more hedges plus aggressive mappings (`configuration→cfg`, `and→&`, `with→w/`). Adding a rule = edit the JSON + add a round-trip fixture under `test/fixtures/` + re-run the evals benchmark.
- **Compression is lossy by design, expansion is lossy too**: `expand` restores abbreviations but never dropped fillers/articles — round-trip preserves technical tokens exactly, prose only approximately. Tests (`test/compress.test.ts`) pin: technical-token preservation, deterministic output, intensity ordering (ultra ≤ lite token count), and the boundary-space regression (prose→preserved-token seams must not fuse, e.g. `at /tmp/out.log` must not become `at/tmp/out.log`).
- **Privacy before compression**: `redactPrivate` strips `<private>…</private>` (non-greedy, dotall, case-insensitive) and defensively truncates from an unclosed tag to end-of-input; `redactSecrets` masks secret-shaped substrings (PEM blocks, Bearer tokens, `sk-…`, `AKIA…`, `ghp_/github_pat_`, Slack `xox…`, and generic `key=value` assignments whose key ends in a secret word) with `[REDACTED]`. A `looksSecretish` gate (≥8 chars, not a function-call shape, not a plain dictionary word) keeps false positives off ordinary source code. Neither redactor ever logs or echoes redacted content.
- **Zero runtime dependencies**: pure TypeScript, only devDeps (tsup/typescript/vitest). Built as ESM with `tsup` (`build` = `tsup src/index.ts src/lexicon.ts --format esm --dts --clean`); `src/lexicon.json` ships in the npm `files` list.
- **Public surface is exactly two export roots** (`package.json#exports`): `.` (index re-exports `compress`, `expand`, `tokenize`/`Segment`/`SegmentKind`, `redactPrivate`, `redactSecrets`, `countTokens`, `Intensity`) and `./lexicon` (the typed lexicon accessors). Internal files are not imported across package boundaries.

## Flow

Write path: caller (hook handler → `MemoryStore.addObservation`) → `redactPrivate` → optional `redactSecrets` (per `settings.privacy.redactSecrets`) → `compress(text, { intensity })` → only prose segments are mutated (removePhrases for pleasantries/hedges/fillers/articles longest-first, abbreviate with case preservation, collapseWhitespace with boundary-space preservation) → compressed string stored. Human read path: stored row → `expand()` → abbreviations restored, preserved tokens untouched. Model read path: callers may request `expand=false` and receive the compressed stored form. `countTokens` (`max(wordCount, round(chars/4))`) gives the before/after metric used by `evals/` and CLI output.

## Integration

- **Downstream (consumers)**: `packages/core` (`memory-store.ts` imports `compress`, `expand`, `redactPrivate`, `redactSecrets` — the write boundary that enforces rule 1 and does privacy before compression); `apps/worker` (`server.ts` expands for the viewer API, `embed-loop.ts` expands before embedding so semantic search matches human text, not caveman grammar); `apps/mcp-server` (`server.ts` uses `redactPrivate`/`redactSecrets` on tool inputs; `get_observations` expansion happens exactly once inside `MemoryStore`); `apps/cli` (`commands/compress.ts` exposes `compress`/`expand`/`countTokens` as user commands, `opencode-bridge.ts` expands session summaries).
- **Upstream (dependencies)**: none — this package depends on nothing, sits second in the chain (`config → compress → storage → …`), and everything else builds on it.
- **Gates**: any change to compressor, lexicon, or tokenizer requires `pnpm --filter @cavemem/compress test` green (round-trip + technical-token preservation + benchmark corpus ≥30% compression in `test/fixtures.test.ts`); the `evals/` package imports `compress`/`countTokens` for the token-savings benchmark; PRs touching this package need a changeset entry.
