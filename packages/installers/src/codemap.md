# packages/installers/src/

## Responsibility

Implementation of the installer system: the `Installer` contract (`types.ts`), the nine-IDE registry (`registry.ts`), the per-IDE modules (`claude-code.ts`, `codex.ts`, `copilot.ts`, `augment.ts`, `opencode.ts`, `gemini-cli.ts`, `cursor.ts`, `antigravity.ts`, `bob.ts`), shared filesystem primitives (`fs-utils.ts`), and the Windows `sh` probe (`windows-sh.ts`).

## Design

- **`types.ts`** defines `InstallContext` (`ideConfigDir`, `cliPath`, `nodeBin`, `dataDir` — `nodeBin` exists because Windows can't exec a raw `.js`, EFTYPE), `CaptureLevel` (`'full' | 'partial' | 'none'`, surfaced in `cavemem status` per issue #58), and the `Installer` interface (`detect`/`install`/`uninstall`, install/uninstall return `string[]` messages).
- **`registry.ts`** declares the `IdeName` union and the `installers: Record<IdeName, Installer>` map; `getInstaller` throws `Unknown IDE: <name>. Known: …`. `index.ts` re-exports the registry and the `windows-sh` API (`checkWindowsSh`, `resolveShDefault`, `WINDOWS_SH_MISSING_WARNING`).
- **`fs-utils.ts`** — `readJson` (fallback on missing/corrupt), `writeJson` (mkdir -p, 2-space, trailing `\n`), `shellQuote` (bare-token regex whitelist; backslashes deliberately excluded so MSYS-bash doesn't strip them from Windows paths — double quotes preserve them under both cmd.exe and sh), `deepMerge` (recursive over plain objects; arrays replaced wholesale).
- **`claude-code.ts`** (`capture: 'full'`) — hooks for all five events into `~/.claude/settings.json`, stripping prior cavemem entries (`isCavememHookEntry` matches `hook run <id>`) while preserving user hooks; when user hooks were preserved it backs the file up as `<path>.pre-cavemem-<Date.now()>`. Hook commands stay plain command strings (no `args` exec-form / `shell` field — see in-source #57 comment: an unsupported field silently ignored by an older build must be a no-op, not a hook that stops firing). MCP goes to `~/.claude.json#mcpServers` via `deepMerge`; legacy `settings.mcpServers.cavemem` is migrated out.
- **`codex.ts`** (`capture: 'full'`, notes `no SessionEnd event`) — four events; `config.toml` round-tripped with smol-toml (`readToml`/`writeToml` return `{}` on parse failure) setting `features.codex_hooks = true` and `mcp_servers.cavemem`; hooks live in a dedicated `hooks.json`; SessionStart carries a `statusMessage`. Uninstall deliberately leaves `features.codex_hooks` alone (other tools may rely on it) and cleans the never-read legacy `config.json`.
- **`copilot.ts`** (`capture: 'full'`, notes `no SessionEnd event`) — Copilot hook payloads are deliberately Claude-Code-compatible so handlers need no translation. Hooks go to `~/.copilot/hooks/cavemem.json` — that directory loads every `*.json` independently, so cavemem owns a dedicated file rather than merging into a shared one; if the emptied file is cavemem-owned, uninstall deletes it. MCP goes to VS Code's *user-level* `mcp.json` (platform-specific `vscodeUserDir`, env-overridable for tests) with the root key `servers` and explicit `type: 'stdio'`.
- **`augment.ts`** (`capture: 'full'`, notes `no UserPromptSubmit event`) — Augment rejects inline command strings, so `writeWrapper` emits thin wrapper scripts (`<hookId>.sh` chmod 0755, or `.cmd` with CRLF on win32) under `~/.augment/cavemem-hooks/` that `exec` the CLI. `PostToolUse` requires a `matcher: '.*'`; `Stop` needs `metadata.includeConversationData` or the turn-summary capture would silently store nothing; session events reject a matcher. Hooks + `mcpServers` live in one `settings.json` written once; ownership detection is by wrapper-dir prefix (`isCavememGroup`).
- **`opencode.ts`** (`capture: 'full'`, notes `via bundled bridge plugin, not hooks.json`) — MCP entry `mcp.cavemem` (array-form command) in `~/.config/opencode/opencode.json` (honors `XDG_CONFIG_HOME`); symlinks `opencodeBridge.js` from the CLI install dir into `plugins/cavemem.js` (removing a stale link first) and lists `file://./plugins/cavemem.js` in the `plugin` array so auto-load survives plugin-dir overrides; migrates the stale `mcpServers` key a prior version wrote and cleans legacy `~/.opencode/config.json`.
- **MCP-only installers** (`capture: 'none'`) — `gemini-cli.ts` (`~/.gemini/settings.json`), `cursor.ts` (`~/.cursor/mcp.json`), `antigravity.ts` (`~/.gemini/config/mcp_config.json`), `bob.ts` (`~/.bob/mcp.json`): all are the same minimal deepMerge-in / delete-out pattern; antigravity and bob additionally return an explicit query-only WARNING string so users know these IDEs never capture.
- **`windows-sh.ts`** — `checkWindowsSh({ platform?, resolveSh? })` returns the multi-line `WINDOWS_SH_MISSING_WARNING` (plain text for colorizing/asserting) when `sh` is missing on win32, else `null`; `resolveShDefault` probes with `spawnSync('sh', ['-c', 'exit 0'], { stdio: 'ignore', windowsHide: true })`. Both options are injectable so non-Windows CI can exercise the win32 branch without shelling out.

## Flow

Every hook-writing installer follows the same sequence: read current config (fallback `{}`) → filter out prior cavemem entries (idempotency) → append fresh entries naming `nodeBin cliPath hook run <id> --ide <id>` → `deepMerge`/preserve user content → single `writeJson`/`writeToml` → return progress messages. Uninstall mirrors it: strip cavemem entries, delete emptied keys (or the cavemem-owned file), report.

## Integration

- Consumed by `apps/cli` via `getInstaller` / `installers` from `registry.ts` and `checkWindowsSh` from `windows-sh.ts` (doctor/status health checks).
- The commands these modules write into IDE configs are the runtime bridge to `apps/cli` → `@cavemem/hooks#runHook`; `opencode.ts` additionally symlinks `opencodeBridge.js` shipped from the CLI package.
- Depends on `@cavemem/config` and `smol-toml` only; tested by `test/installers.test.ts` with injected temp contexts.
